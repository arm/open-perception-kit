## 📦 Container

The repository supports multiple development platforms.  
To set up a usable Docker environment, first run `setup-container.sh` on the host OS and select the appropriate platform:

- **Default container:** Works everywhere (hopefully), but without hardware acceleration.  
- **PC hardware-accelerated x64 Linux:** Runs on a Linux PC with video hardware acceleration tunneled into the container.  
  **Note:** This option is no longer supported.

This script generates the `Dockerfile` and `devcontainer.json`.  
You can then proceed as usual:

- Open the Dev Container: `code .`  
- Then click the *Reopen in Container* button in VS Code.

## 🛠️ Build and Test

Basic tasks can be performed in the Dev Container terminal using the shell scripts:

```sh
./scripts/build-elements.sh debug   # Build elements in debug mode using Meson/Ninja
./scripts/build-elements.sh release # Build elements in release mode
./scripts/test-elements.sh onnx     # Play a video pipeline that includes ONNX YOLOv8 inference
./scripts/test-elements.sh onnxweb  # Same as above, but with a WebRTC endpoint
```

## 🍎🐧 macOS / Linux Setup

To play videos produced inside the Dev Container, you need **ffmpeg** installed on the host OS:

```sh
# On macOS
brew install ffmpeg

# On Ubuntu 24.04
sudo apt install ffmpeg

# This works on both systems
ffplay -hide_banner -fflags nobuffer -flags low_delay -f mpegts udp://127.0.0.1:5000
```

This runs `ffplay` in continuous mode, allowing the container to publish videos at any time.  
At the beginning of playback, `ffplay` may fail to find a keyframe in the stream and display several error messages such as:

```
[h264 @ 0x7a8f04109700] non-existing PPS 0 referenced
[h264 @ 0x7a8f04109700] decode_slice_header error
```

These should disappear within a few seconds, after which `ffplay` will begin displaying the augmented video.

## 🧠 Setting Up Visual Studio Code for IntelliSense and Symbolic Debugging

### IntelliSense

To enable *Code Completion*, *Go to Definition*, and similar features in VS Code, **clangd** is used.  
The `clangd` language server is already installed via the Dev Container `Dockerfile`. You only need to install the [VS Code clangd extension](https://marketplace.visualstudio.com/items?itemName=llvm-vs-code-extensions.vscode-clangd) inside the container.

`clangd` relies on the compilation database (`compile_commands.json`) automatically generated by Meson during build directory setup.  
After the first call to `./scripts/build-elements.sh [debug|release]`, this file should appear in the build directory.  
Since `clangd` looks for `compile_commands.json` in the project root, create a symbolic link to it in the Dev Container:

```sh
# Inside the Dev Container
evgoblin@amp-dev-forge:/work$ ln -s ./development/build/compile_commands.json .
```

After reloading the VS Code window, IntelliSense should work properly.

---

### Debugging

For symbolic debugging, install the [Microsoft C/C++ extension](https://marketplace.visualstudio.com/items?itemName=ms-vscode.cpptools) in VS Code.  
Other dependencies (e.g., `gdb`) are already included via the `Dockerfile`.

As both **clangd** and the **C/C++ plugin** support IntelliSense, it is recommended to disable this feature in the C/C++ plugin.  
**clangd** provides more accurate and efficient IntelliSense functionality.

After clicking *Run and Debug (Ctrl+Shift+D)* in VS Code, create the following `launch.json` in the `./.vscode` directory:

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "onnx",
            "type": "cppdbg",
            "request": "launch",
            "program": "/usr/bin/gst-launch-1.0",
            "args": [
                "filesrc", "location=/work/etc/videos/00.mp4", "!", "decodebin", "!",
                "videoconvert", "!",
                "ampinfer", "model-path=/work/etc/models/yolov8n/yolov8n-fp32.onnx", "imgsz=640", "!",
                "videoconvert", "!", "x264enc", "tune=zerolatency", "speed-preset=ultrafast", "!",
                "mpegtsmux", "!",
                "udpsink", "host=\"127.0.0.1\"", "port=5000", "sync=false", "async=false"
            ],
            "stopAtEntry": false,
            "cwd": "${workspaceFolder}",
            "environment": [
                { "name": "GST_PLUGIN_PATH", "value": "${workspaceFolder}/development/build" }
            ],
            "externalConsole": false,
            "MIMode": "gdb",
            "setupCommands": [
                {
                    "description": "Enable pretty-printing for gdb",
                    "text": "-enable-pretty-printing",
                    "ignoreFailures": true
                },
                {
                    "description": "Set disassembly flavor to Intel",
                    "text": "-gdb-set disassembly-flavor intel",
                    "ignoreFailures": true
                }
            ]
        }
    ]
}
```

You can add additional configurations (`onnx2`, `onnxweb`, `ampinfer`, etc.) as defined in `./scripts/test-elements.sh`.

After starting a debug session in VS Code, standard debugging features—such as breakpoints, step over, and step into—will be available.
